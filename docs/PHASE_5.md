# 阶段五：不可变数据集与完整交付

## 这一步解决什么问题

审核工作台保存的是“现在怎样判断这个样本”。科研实验还需要知道“当时使用了哪些样本和标签”。
本阶段新增数据集、固定版本与Manifest清单：发布后，即使继续改人工标签，旧版本的成员、标签和
下载字节都不改变。数据资产中心现在也可以在网页中扫描文件、分段、查看接入历史和执行质量检查。

```mermaid
flowchart LR
    F[受控原始文件] --> A[网页扫描与区间索引]
    A --> W[后台质量检查与模型建议]
    W --> H[人工审核及历史]
    H --> P[选择预览 固定期望身份]
    P --> J[PUBLISH 持久化任务]
    J --> C[Worker 事务外完整校验源]
    C --> T[同一数据库快照 生成成员与清单]
    T --> S[校验后封存 与任务成功一起提交]
    S --> D[下载确切 Manifest 字节]
```

## 如何启动与演示

需要Python 3.11+、已启动的Docker Desktop Linux引擎，以及首次安装依赖/镜像时的网络。
在仓库根目录执行：

```powershell
python scripts/quickstart.py
# 同时生成一批独立合成IQ，并运行完整HTTP演示：
python scripts/quickstart.py --demo
```

脚本创建/复用项目虚拟环境，按锁文件安装依赖，缺少.env时生成随机配置，运行Compose迁移、
API、两个Worker和前端。没有演示账号文件时创建三个随机密码账号，并幂等登记Mock模型。
不会覆盖.env或账号文件，不会清空数据库或删除原始数据。依赖安装成功后保存本地摘要，重复启动
且依赖未变时跳过安装；应用源码以editable方式供本机调试。

工作台默认 <http://127.0.0.1:18080>，API文档 <http://127.0.0.1:8000/docs>。
本地随机密码见 `artifacts/demo-accounts.json`。该文件、.env、IQ、Manifest演示产物和备份均被Git忽略。
若账号文件与另一个数据库卷不匹配，应恢复对应环境或使用管理CLI创建新账号，脚本不会自动重置密码。

`--demo` 的操作均通过真实登录和HTTP完成：生成BIN/HDF5 → 扫描 → 分段 → 质量 → Mock推理 →
用审核账号写明确标识为演示的人工结论 → 研究账号发布v1.0.0 → 修改一个标签 → 发布v1.0.1 →
验证v1下载字节不变。每版4个已审核样本。报告为 `artifacts/phase5-demo.json`，v1实际下载清单为
`artifacts/phase5-demo-manifest.json`。这些标签只演示软件流程，不是实测调制类别真值。

## 网页使用顺序

1. 管理员在“数据资产”输入相对目录并提交扫描。采集文件仍需显式.iq.json和.done完成标记。
   扫描完成后检查新增/跳过/错误计数，不能只看任务SUCCEEDED就认为所有文件有效。
2. 搜索相对路径，选中源文件，查看完整哈希和元数据。设置窗口、步长、起止采样，提交分段任务。
   点击“查看片段与预测”，可限定当前文件，再执行质量检查和模型预标注。
3. 审核人员或管理员查看波形、频谱和模型建议，保存自己的结论。研究人员只读审核数据。
4. 研究人员或管理员在“数据集管理”创建数据集，设置版本名、源文件、审核状态和类别。
   默认仅人工标签、仅REVIEWED。源文件不选时按其他筛选条件匹配整个当前受控根目录。
5. 点击“预览选择”，确认数量、类别分布、人工/模型来源和样例。没有可用样本会明确拒绝。
6. 点击“发布不可变版本”，等待后台完整校验。只在成功封存后出现在版本列表中。
7. 选中历史版本查看固定成员，下载Manifest。页面会核对下载字节的SHA-256再保存文件。

“后台任务”可按类型、状态筛选，查看参数、结果、事件和错误；管理员可重发失败任务，研究人员
还可重发PUBLISH。重发创建新generation并保留原失败历史。若筛选已变化，应重新预览并发新请求，
重发旧payload不会自动接受新样本。原发布者被禁用后旧请求不能继续发布，新发布需由有效发布者提交。

## 选择与标签来源规则

- HUMAN_ONLY为默认，只有实际人工历史记录能成为标签来源，不会用预测补空缺。
- MODEL_ALLOWED必须显式指定model_version_id；已有人工结论始终优先，包括UNKNOWN。
  只有没有人工标签记录时，才使用该版本的模型预测。
- 使用Mock模型补充标签还须allow_mock_predictions=true；清单保留is_mock和模型定义。
  已人工确认但参考了Mock的记录仍以HUMAN为来源，annotation中保留参考预测及其Mock标识。
  contains_mock_predictions特指直接采用Mock预测作为MODEL标签的成员。
- 默认review_status=REVIEWED；要纳入未审核预测，需要明确选PENDING或全部状态。
- 预览给出selection_digest，含筛选规则、片段/文件/配置身份及具体人工或预测记录ID。
  发布必须提交该摘要；预览后来源变化将返回SELECTION_CHANGED，要求重新确认。

## 发布事务为何可靠

发布通过PUBLISH队列任务执行，POST返回202和真实job_id。完整IQ哈希可能耗时，因而放在Worker，
没有放进HTTP处理函数。准备阶段只产生有界内存计划，没有正式数据库版本或磁盘输出。

完成阶段使用REPEATABLE READ，并沿用阶段三的job_id/worker_id/execution_version/租约校验。
选择在完成事务的同一个一致视图中重新求值，不把事务外动态标签当作最终快照。若审核在这个视图
建立后发生，发布会保留该视图里的历史；不会混入后来的标签。序列化失败按现有有限重试处理。

在同一事务中，服务锁源路径并复核ACTIVE及观察信息，插入版本、成员，生成规范UTF-8 JSON，
计算确切字节SHA-256，再封存并将任务置SUCCEEDED。最后租约检查失败、SQL失败或中途异常，
版本、成员、Manifest和成功状态一起回滚。重复完成相同有效结果只返回第一次结果。

使用数据库保存Manifest文本，下载直接返回这些字节，避免数据库与磁盘文件的跨资源双写。
实际IQ仍以源文件和采样区间引用，不生成海量片段副本。不能把它描述为严格exactly-once执行。

## 数据库级不可变约束

新增datasets、dataset_versions、dataset_version_items，以及processing_jobs.dataset_id外键。
dataset名称/描述在MVP中也不提供编辑或删除，减少历史名称歧义。

版本先在创建事务内处于unsealed，再一次性封存；creation_xid由数据库记录完整事务身份。
成员INSERT必须先锁父版本，确认未封存且属于同一个创建事务，再验证文件、标签、策略和筛选条件。
冻结JSON由数据库从原始身份/处理配置/不可变标签记录生成，不能随意伪造。

封存时触发器验证成员数量、实际字节哈希，以及Manifest解析后是否精确等于固定成员生成的清单。
延迟约束触发器禁止未封存版本提交。封存后版本拒绝UPDATE/DELETE，成员拒绝INSERT/UPDATE/DELETE，
因此不仅防止修改，也防止事后偷偷加样本。数据库管理员若主动禁用触发器仍可绕过，这是权限边界。

Manifest固定：数据集身份和名称、版本ID和发布者、筛选策略、每个片段对应的源路径和完整校验值、
解释元数据、采样区间、处理配置/读取版本、具体人工历史或预测、模型版本与Mock标识。
成员按segment UUID排序，JSON固定键序/分隔符、UTF-8、拒绝NaN。数据库原生SHA-256无需pgcrypto扩展。

具体实现见 `backend/app/services/datasets.py`、`models/datasets.py`、`api/datasets.py`，
迁移 `0005_datasets` 及 `backend/alembic/sql/0005_snapshots.sql`。
官方语义参考：[一致视图](https://www.postgresql.org/docs/17/applevel-consistency.html)、
[约束触发器](https://www.postgresql.org/docs/17/sql-createtrigger.html)、
[二进制SHA-256](https://www.postgresql.org/docs/17/functions-binarystring.html)。

## 验证与证据

后端覆盖22项数据集测试（含参数化）：清单追溯/UTF-8哈希、旧版本不变、Mock显式许可、UNKNOWN
人工优先、空集/超限、两次选择核对、完整哈希改写检出、一致视图下并发审核、部分结果回滚、
租约到期回滚、成功重放、唯一版本竞争、封存后直连SQL改/删/加均拒绝、并发追加父行锁、
未封存不可提交、伪造清单/来源/冻结数据拒绝，以及角色、分页、root隔离和请求幂等。

浏览器测试源码在 `frontend/tests/publishing.spec.js`：通过页面扫描/分段/质量/预标注/人工审核，
创建数据集，下载v1，修改标签再发布v2，断言v1实际下载字节不变。它每次创建独立小型合成输入，
可重复运行，不依赖某个旧样本仍未审核。阶段四多人冲突测试继续保留。

实际完整测试数量、执行时间、界面截图和最终环境记录见 [TESTING.md](TESTING.md)。

## 备份和恢复验证

```powershell
.\.venv\Scripts\python.exe scripts/backup.py --verify
```

脚本将pg_dump自定义格式二进制直接写入新的artifacts/backup-*.dump，避免Shell文本重定向改变字节。
--verify会新建随机隔离数据库，pg_restore后核对schema及全部Manifest，再删除本次新建的恢复库；
不覆盖或清空开发数据库。备份包含用户哈希及会话摘要，应当作为私有文件保管。
它只备份PostgreSQL；IQ、模型文件和私有配置需要独立备份与恢复规划。

## 当前边界与后续工作

MVP单版最多10000成员、100个源文件、16MiB Manifest；没有性能容量承诺。源选择可按raw_file_ids、
segment_ids、labels和review_status组合。网页源文件选项一次100条，可用路径搜索缩小范围。
大型IQ导出包、对象存储、任务取消/抢占、用户自助管理、复杂筛选和互联网部署仍不属于本次范围。

原始文件的留存依赖采集端完成后不再修改、只读挂载与完整校验；数据库固定引用不能物理阻止宿主机
改写或删除。源丢失后仍能下载历史元信息，但不能保证源IQ还可读取；未来导出IQ时必须再次完整校验。
没有真实模型权重，本次只验证Mock工程流程，真实推理、模型精度及长期负载需另行验证。
默认账号级登录限流、localhost端口和开发数据库角色适合本机演示；外网部署需补TLS、最小权限、
监控与可靠存储。五个阶段的核心业务链路完成，不等于已验证生产高可用或真实信号识别效果。
